## 7. KEY DESIGN DECISIONS

| Keputusan | Pilihan | Alasan |
|---|---|---|
| **Bahasa** | Python 3.11+ | Ekosistem terbesar, semua provider ada SDK |
| **Provider utama** | OpenRouter | 1 API key, semua model (Claude, GPT, Gemini, DeepSeek) |
| **Database** | SQLite | Zero-dependency, portable, cukup untuk single-user |
| **Vector store** | ChromaDB / sqlite-vec | Local, no server, lightweight |
| **Sub-agent isolation** | `multiprocessing` | True process isolation, GPU-friendly |
| **Tool safety** | Approval gate | Terminal + git destructive = user confirmation |
| **Konfigurasi** | YAML | Human-readable, easy backup, version control |
| **Logging** | structlog | Structured JSON, searchable, production-ready |
| **Agent loop** | Custom while loop | Lebih fleksibel daripada framework (LangChain, etc) |
| **Memory limit** | Configurable | Auto-summarize old context, sliding window |

## 8. PRINSIP PENTING

```
1. WORKING CODE > perfect code
   Tiap fase harus ada milestone yang bisa di-test.

2. STDLIB FIRST
   Jangan nambah dependency kalau stdlib udah cukup.

3. GRACEFUL DEGRADATION
   Kalau 1 provider down, auto-switch ke fallback.

4. MEMORY FIRST
   Agent tanpa memory = chatbot. Harus ingat antar session.

5. SELF-IMPROVE
   Tiap sukses → simpan pattern. Tiap gagal → catat pitfall.

6. GATED DESTRUCTIVE
   Terminal, git push, file delete = user approval required.

7. PROVIDER AGNOSTIC
   Jangan lock-in ke 1 provider. Bisa ganti kapan aja.

8. ON-DEVICE READY
   Jalan di laptop, server, Android/Termux. No cloud required.
```
